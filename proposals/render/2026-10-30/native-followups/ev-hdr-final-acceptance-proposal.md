Paths below are repository-relative.

- **EV reaches identity once.** `render_workspace_shot.rs:415-437` keeps a local slider value during pointer-down and commits the exposure edit on release through edit_settings; `71-86` copies the saved EV into the active draft. `render_workspace.rs:879-926` constructs the complete Interactive runtime request. `render_workspace_cpu.rs:363-385` puts draft EV in raytrace.exposure_ev and sets outer settings.exposure_ev to0. Constant RGB/intensity or HDR source/digest/rotation/intensity/samples are included. A no-change image on an unsupported Model Preview is not the oracle for the traced image. During the exposure drag, the current source does not promise every local slider value has already entered the request.
- **Identity invalidation and error latch.** `render_workspace_interactive.rs:139-181` compares scene identity, document UID/revision, camera, stale state and the full request Result<Value,String>. Changes create a visual revision and invalidate old unpaused pixels. `198-231` gives final work/results priority and pauses a request with an error. A stable error does not create a new intent each frame. A genuine correcting edit resumes the error path unless user_paused; `386-398` explicitly Resume-checks the latest request and starts a fresh capture. An unchecked HDR cannot be repaired by Resume alone.
- **Two different HDR errors.** `render_workspace_hdr.rs:98-106` inspects a file before accepting metadata; `137-153` serializes expected_sha256 for a captured path, resolves embedded IDs, and rejects empty/pending inputs. `177-213` marks typed text pending and exposes Check HDR file. `render_workspace_environment.rs:441-448` intentionally avoids saving unchecked paths. `283-299` preserves a checked local path after saving embedded bytes, so a local-path request can still fail if that external file later disappears. Do not mistake that for loss of an embedded document resource. `docs/render-cpu-workspace.md:92-127` states the source limits, primaries/digest contract and immutable captured-job behavior.
- **Final isolation.** `render_workspace_interactive.rs:275-282` only fills its own provisional cache; `336-354` suspends/restricts Interactive for actual finals or displayed retained results. `render_workspace_ribbon.rs:169-170` chooses view.completed for export, and `render_workspace.rs:1758-1767` retains that job ID across the picker with document-identity validation. A late Interactive reply is additionally checked against UID/ticket/revision/context in interactive.rs:98-121. The source does not promise export of the newest draft: it promises export of the identified retained final.

Source regression functions already exist for runtime HDR/EV lowering(6726), invalid HDR selection(7183), actual HDR read error/Resume(7204), user-pause preservation(7247), final-priority/error isolation(7341), and final export isolation(6944). Reading them is not running them and does not replace the missing native journeys. No new duplicate test harness is proposed.

## Four concrete original journeys for Root's next admitted app

**Common setup:** isolated owned synthetic design and explicit named CPU shot; fixed camera and supported modest quality; Interactive opt-in. Record the new actual app/source binding and actual preview dimensions. Keep a neutral matte cube for J1/J2 and a fully metallic smooth reflector for J3, admitted through existing CPU controls. No user design, environment or installed-release substitution. These are new native permutations, not a repeat of C9A's appearance/preset/pause/camera checks.

### J1 — EV commit and reversal, without changing final intent

Use a mid-grey matte face with unclipped lighting. Complete baseline EV0, then use the actual Shot exposure control to commit +1, -1 and0 separately, allowing each to reach a new provisional16SPP frame. Capture the EV number plus status/image after release. Also observe one slow drag before release: distinguish the local numeric display from the committed request rather than claiming a dropped invalidation during pointer-down. Undo/Redo one committed exposure change through the normal UI and record refresh.

Acceptance: after each committed edit a fresh provisional state/image appears; a suitable unsaturated face becomes brighter at+1 and darker at-1, returning to the baseline at0 with unchanged camera/material/lights. Do not demand twice the PNG byte value: transfer/tone mapping and sampling make that a false oracle. Preserve final size/quality. The one-EV-authority arithmetic is a source finding; visual monotonicity alone cannot certify the exact exposure transfer. Final render/export are not started in J1.

### J2 — pending HDR selection to Error, then valid Constant recovery

From a valid running preview select HDR and type an owned, uninspected path, without opening or publishing a private picker. Record the specific Inspect/Check requirement and Interactive Error. Press Resume once: it must refuse the same missing admission rather than report success. Wait without further input and record that Error remains, with no repeated Updating/capture loop. Change the source to Constant with a valid bounded colour/intensity, then let the new current request finish. Repeat only the recovery suffix while deliberately user-paused: a correcting edit must leave it paused/out-of-date until explicit Resume.

Acceptance: clear error and usable recovery through a real input correction; no invented current frame. A failed file inspection must not silently substitute an unrelated environment. Do not judge Constant by diffuse brightness on the cube: CPU Constant is secondary reflected/transmitted radiance, not direct diffuse light or the background (cpu-workspace.md:92). This journey qualifies state/recovery, not Constant transport fidelity.

### J3 — verified asymmetric HDR, input changes and same-intent file recovery

Root may prepare a tiny **original** 2:1 Radiance fixture in its owned evidence folder under its separate grant. Proposed bounded header: FORMAT=32-bit_rle_rgbe and explicit PRIMARIES=0.64 0.33 0.30 0.60 0.15 0.06 0.3127 0.3290; two distinct red/blue hemispheres, not uniform grey. No fixture file is created by this proposal. The existing original header convention is in render_workspace_tests.rs:3363. Use a metal reflector that passes the actual CPU HDR admission; an unsupported reflection scope stays BLOCKED, never silently downgraded.

Choose/check that source in the actual UI; record digest, dimensions and metadata. With Interactive accepted, commit rotation0→180→0 and intensity1→0→1 using existing Environment controls, holding EV/camera fixed. The coloured reflected pattern must respond and return without claiming a complete convergence/transport proof; intensity0 removes the HDR contribution, not necessarily direct lights or the image background.

For the **worker I/O** suffix, use only that temporary owned file: after successful inspection and with the panel still showing a checked local path, make it temporarily unavailable through the agreed Root-owned filesystem/UI action, then make a harmless camera edit to force a fresh capture. Record the source read error. Restore the same bytes without changing UI intent: Error must remain latched until explicit Resume, then recover. Alternatively explicit recheck of a genuinely new owned HDR is an actual input change. Do not delete or rename a shipped resource or touch a user's HDR; if file operations are outside Root's current grant, leave this suffix NOT RUN. Never assume the same behavior for an embedded-resource-only request.

### J4 — final A survives preview B, error and final priority

Explicitly start and finish one small CPU final A through the UI (e.g.320×240 if admitted); record its job identity, dimensions, captured revision and original exported PNG hash. Start/return to Model/Interactive and commit a visibly different EV, producing preview B. Trigger J2's pending-HDR error as a further draft change. Select retained Result A and export it again through the normal UI to another owned filename. The PNG bytes/hash and dimensions must still match A; it must not become B or an empty/error frame. A stale-result warning is correct because the document/draft has changed.

Start a second final only under its normal admission. While it is active, record Interactive's final-priority reason and that Resume cannot start competing work. On completion the new final becomes the identified retained result; on cancellation/failure the original retained A must remain available. This is a proposed extension of J4, not permission to inject an error or cancel a foreign job. Never infer retained-final identity from a screenshot of similar pixels alone. Capture picker-free before/after states; inspect only the exported owned file bytes afterwards.
