# Explicit internal output limits: seven-helper preparation

Source-only reviewed V2, NOT APPLIED/FORMATTED/COMPILED/RUN. Seven existing helpers share explicitly bounded internal RenderLimits policies for presentation, bloom, photographic effects, EXR encoding/decoding, PNG and regrade. Public GPU wrappers retain their current limits and supported-image behavior. The policy is not a host reservation or a CPU capability. No CPU host caller, raw transport, WorkBudget charging, EXR producer metadata or feature enablement is implemented here.

Thirteen original proposed tests preserve the nine previous declarations. They include independent linear radiance/coverage and bloom-kernel oracles, narrow8193x1 threading, exact-fit and hostile-policy refusal, default bytes and cancellation/validation ordering. The first source review identified changed legacy PNG cancellation precedence before new retained-capacity checks. V2 restores the original immediate cancel check after the original dimension/length checks; the other six candidates and all tests remain byte-identical. Independent delta review found no new source blocker. No image, compiler, Clippy or runtime result is claimed.

CPU enablement still requires captured raw scene-linear samples, correct acquired peak-buffer leases and cumulative work, coherent per-request output limits, publication/cancellation and real end-to-end tests. Passing a caller-created policy alone never acquires memory. The implementation rejects policies beyond existing Workstation maxima without raising those maxima. Do not mix this preparatory patch with an unrelated host overlay.
