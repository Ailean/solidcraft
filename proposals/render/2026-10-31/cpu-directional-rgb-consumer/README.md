## Proposed runtime contract

The API option `directional_shadow_transmission` defaults to false and is omitted from serialized requests when false. True mode requires shadows and selected valid dielectrics; unsupported inputs are refused explicitly. The existing UI checkbox for transmitted shadows on a body is NOT connected to this new option. The UI adapter and per-body intent/mixed-material contract are separate work; a global flag must not be treated as consent to ignore or clear those controls.

Scope is straight directional-light connections through the existing foundation's certified thin sheets and disjoint aligned boxes. Unselected geometry remains opaque. This is not general CPU/GPU parity, arbitrary interiors, refracted shadow connections or caustics. Existing camera StrictTir, Beer attenuation, work/capacity limits, cancellation and error behavior remain separate. No epsilon, depth, quality fallback or admission-limit increase is proposed.

The task owns one visibility context/cursor and bounded per-pixel RGB results. The proposal connects the ordinary, retained-effects and unselected optical-hit directional paths, with completion/reuse/release checks. Source review does not establish Rust borrowing, Send/layout/size, actual resource admission, scheduling, runtime correctness or throughput.
